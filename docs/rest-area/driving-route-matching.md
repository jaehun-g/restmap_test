# 주행 경로 휴게소 판별 로직

## 검토한 방법과 한계

아래 1번은 기존 구현, 4번은 현재 구현이다. 2번과 3번은 대화에서 검토한 방식으로, 실제로 구현하거나 성능·정확도를 측정한 결과는 아니다.

### 1. 최초 구현: 경로 폴리라인과의 거리

카카오모빌리티에서 받은 주행 경로의 폴리라인과 휴게소 좌표 사이의 최단 거리를 계산한다. 이 거리가 1,500m 이내면 경로 주변 휴게소로 표시하고 출발지부터 경로 진행 순서로 정렬한다.

- **문제 상황:** 고속도로 반대편 휴게소나 가까이 평행하게 지나는 다른 노선의 휴게소도 1,500m 이내라면 표시될 수 있다.
- **한계:** 거리만 확인하므로 주행 방향과 휴게소 진입 가능 여부를 알 수 없다. 반대로 실제 진입이 가능한 휴게소라도 대표 좌표가 1,500m 밖이면 제외된다.

### 2. 경로 구간의 노선명과 거리 비교

거리로 후보를 찾은 뒤, 휴게소와 가까운 경로 구간의 도로명과 휴게소의 노선명을 비교하는 방법을 검토했다. 이를 위해 카카오 응답의 도로별 이름과 좌표를 함께 보존하고, 서로 다른 표기를 정규화해야 한다. 현재는 도로 좌표들을 하나의 경로로 합치고 대표 도로명만 별도로 보관한다.

- **문제 상황:** 분기점이나 평행 도로에서는 휴게소와 가장 가까운 구간이 실제로 휴게소에 연결된 도로가 아닐 수 있다. 같은 노선의 반대 방향 휴게소도 노선명은 일치할 수 있다.
- **한계:** 비교할 구간을 선택하는 과정 자체가 여전히 거리 기반이다. 도로명과 노선명의 표기 차이·누락을 처리해야 하며, 이름이 같더라도 실제 진입 가능성을 보장하지 않는다.

### 3. 카카오모빌리티 경유지 응답 활용

거리로 후보를 추린 다음, 휴게소를 경유지로 넣어 카카오모빌리티에 경로를 다시 요청하는 방법을 검토했다. 기존 경로와 경유지 포함 경로를 비교해 큰 우회나 경로 이탈이 있는지 확인하는 방식이다.

- **문제 상황:** 휴게소 대표 좌표가 반대편 도로나 일반도로로 보정되면 재탐색 결과가 실제 휴게소 진입 경로와 달라질 수 있다. 정상 진입에 필요한 우회와 잘못된 방향으로 진입하기 위한 우회를 구분할 기준도 필요하다.
- **성능 한계:** 후보별 독립 검증은 후보 수만큼 추가 API 호출과 응답 대기가 발생한다. 병렬화하면 대기 시간은 줄일 수 있지만 순간 요청량이 늘어나며, 실제 비용과 지연은 후보 수와 API 응답 시간을 측정해야 한다.
- **경유지 개수의 한계:** 일반 자동차 길찾기는 요청당 경유지를 최대 5개 받을 수 있지만, 하나의 요청은 해당 경유지를 모두 거치는 하나의 경로를 반환한다. 따라서 5곳을 한 번에 요청한 결과만으로 각 휴게소를 독립적으로 검증할 수 없다. 묶음에 우회가 있다면 추가로 분리 검증하는 방법을 고려할 수 있으나 정확도와 호출량의 검증이 필요하다.
- **운영 조건:** 무료 쿼터와 초과 사용 시 제휴 조건을 확인해야 한다. 현재 프로젝트에는 이 재탐색 방식이 구현되어 있지 않다.

### 4. 현재 구현: 거리와 주행 방향 오른쪽 판별

기존의 1,500m 거리 조건을 유지하면서, 각 휴게소와 가장 가까운 경로 선분의 진행 방향을 기준으로 오른쪽 여부를 계산한다. 양방향 휴게소는 좌우와 관계없이 거리 조건을 통과하면 포함한다. 추가 API 요청 없이 기존 좌표를 사용한다.

- **문제 상황:** 가까운 다른 도로의 선분을 기준으로 판별하거나, 휴게소 대표 좌표가 진입로와 떨어진 경우 잘못 포함하거나 제외할 수 있다. 방향 정보가 누락된 양방향 휴게소도 한쪽 방향 시설처럼 처리될 수 있다.
- **한계:** 오른쪽에 있다는 사실만으로 실제 진입 가능성을 보장할 수 없다. 선분 끝점·분기점 주변이나 경로선과 거의 일직선인 위치에서는 좌우가 모호할 수 있다. 경로 주변 주유소는 이 오른쪽 조건을 직접 적용하지 않는다.

## 목적과 처리 흐름

길찾기에서 선택한 주행 경로 주변의 휴게소 중 진행 방향 오른쪽에 있거나 양방향인 휴게소를 지도와 경유 목록에 표시한다. 경로는 카카오모빌리티 길찾기 응답의 도로 좌표를 출발지부터 목적지 순서로 연결한 폴리라인이다.

1. 폐쇄된 휴게소와 좌표가 없는 휴게소를 제외한다.
2. 폴리라인을 연속된 두 좌표로 이루어진 선분으로 나눈다.
3. 각 휴게소와 가장 가까운 유효 선분을 찾고, 선분까지의 거리가 기본 1,500m 이내인지 확인한다.
4. 가장 가까운 선분의 진행 방향을 기준으로 오른쪽에 있는지 판별한다. 양방향 휴게소는 좌우 판별을 통과한다.
5. 경로 시작점부터 가까운 지점까지의 거리순으로 정렬한다.

범위 밖 후보를 빠르게 제외하기 위해 전체 경로와 각 선분의 바운딩 박스를 확장하여 먼저 검사한다. 최종 포함 여부는 박스가 아니라 선분까지의 거리로 결정한다. 출발지·도착지로 지정된 휴게소는 판별 결과에 포함된 경우 지도에 남고 경유 목록과 개수에서는 제외된다.

## 선분까지의 거리

`findItemsAlongDrivingRoute`는 선분 시작점에서 휴게소까지의 거리와 방위각 차이를 이용해 휴게소를 선분 방향으로 투영한다. 투영 지점이 선분 안에 있으면 선분까지의 횡방향 거리를, 시작점 이전이나 끝점 이후면 해당 끝점까지의 거리를 사용한다. 모든 후보 선분 중 거리가 가장 작은 선분을 선택한다.

`offsetMeters`는 선택된 선분까지의 최단 거리이고, `alongMeters`는 경로 시작부터 그 선분의 투영 지점까지 누적한 거리다. 반환값은 미터 단위로 반올림된다. 길이가 0인 선분은 방향을 판별할 수 없으므로 일반 휴게소의 오른쪽 판별에서는 건너뛴다.

## 방위각 계산

`bearing(from, to)`는 두 위도·경도 좌표로 구면 방위각을 구한다. 모든 각도는 라디안이다. 시작점과 끝점의 위도를 각각 `φ1`, `φ2`, 경도 차이를 `Δλ`라고 하면 계산식은 다음과 같다.

```text
y = sin(Δλ) × cos(φ2)
x = cos(φ1) × sin(φ2) − sin(φ1) × cos(φ2) × cos(Δλ)
bearing = atan2(y, x)
```

```ts
function bearing(from: GeoPoint, to: GeoPoint) {
  const delta = radians(to.longitude - from.longitude);
  const left = radians(from.latitude);
  const right = radians(to.latitude);
  return Math.atan2(
    Math.sin(delta) * Math.cos(right),
    Math.cos(left) * Math.sin(right) - Math.sin(left) * Math.cos(right) * Math.cos(delta),
  );
}
```

북쪽은 0°, 동쪽은 90°, 남쪽은 ±180°, 서쪽은 -90°다. 코드의 실제 반환값은 도가 아닌 라디안이며 시계 방향이 양수다.

## 오른쪽 판별

휴게소 `point`에서 가장 가까운 선분의 시작점과 끝점을 각각 `start`, `end`라고 할 때 다음과 같이 두 방위각의 차이를 계산한다.

```ts
const segmentBearing = bearing(start, end);
const pointBearing = bearing(start, point);
const angle = pointBearing - segmentBearing;
const isRight = Math.sin(angle) >= -1e-12;
```

`segmentBearing`은 주행 방향이고 `pointBearing`은 같은 시작점에서 휴게소를 바라보는 방향이다. 두 각도 차이의 사인값이 양수면 오른쪽, 음수면 왼쪽이다. `-1e-12`는 부동소수점 오차를 고려한 허용값이며, 경로선과 거의 일직선인 경우를 포함한다.

예를 들어 선분이 북쪽으로 향해 방위각이 0°이고 휴게소가 시작점의 동쪽에 있어 방위각이 90°이면, 각도 차이는 90°이고 사인값은 양수이므로 오른쪽이다. 선분 방향이 반대로 바뀌면 좌우 판단도 바뀐다.

## 양방향 휴게소

`directionLabel`, `routeDirection`, 휴게소 이름의 괄호 안 내용 중 하나가 양방향 값이면 왼쪽이어도 포함한다. 기존 정규화 함수는 공백을 무시하고 `양방향`, `양방`, `통합` 및 해당 값 뒤에 `방향`이 붙은 표현을 인식한다. 양방향이어도 좌표와 1,500m 거리 조건은 적용된다.

## 주유소 마커

주유소는 오른쪽 판별 없이 경로에서 1,500m 이내인지 확인한다. 이후 경로 주변의 폐쇄되지 않은 휴게소에 연결된 EX 주유소는 별도 마커에서 제외한다. 이때 휴게소 목록은 좌우 조건을 적용하기 전 목록이므로 왼쪽으로 판별되어 숨겨진 휴게소의 연결 주유소도 제외된다. 휴게소에 연결되지 않은 독립 주유소는 남는다.

연결은 기존 시설 매칭을 사용한다. EX 주유소를 대상으로 노선·이름·방향 또는 검증된 연결 정보와 좌표를 확인하며, 휴게소와 주유소 사이의 거리는 300m 이내여야 한다. 매칭되지 않은 주유소에는 연결 휴게소에 따른 제외가 적용되지 않는다.

## 한계

- 좌표와 가장 가까운 선분을 기준으로 하므로 인접 도로, 교차로, 분기점 또는 굴곡 구간에서 실제 소속 도로와 다른 선분이 선택될 수 있다.
- 휴게소의 대표 좌표가 진입로와 다르거나 공용 시설의 방향 정보가 누락되면 결과가 실제 접근 가능 여부와 다를 수 있다.
- 선분의 연장선이나 끝점 가까이에서는 좌우가 불분명할 수 있다. 이 계산은 도로 연결이나 실제 진입 가능성을 검증하지 않는다.
- 경로 주변 주유소 자체에는 오른쪽 판별이 적용되지 않는다.
