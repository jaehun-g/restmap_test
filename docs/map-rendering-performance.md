# 지도 조회·마커 렌더링 성능 개선

작업일: 2026-10-22 (한국시간)

## 변경 내용

### 최초 조회 경량화

- `/api/rest-areas`에서 음식 메뉴 전체 JSON 집계를 제거했다. 현재 요약 지도에서 사용하지 않는 `foodMenuSummary`를 만들기 위해 메뉴 테이블을 읽지 않는다.
- 음식 탭은 기존 `/api/rest-areas/{id}/food-menus`를 통해 필요한 휴게소의 메뉴만 조회한다.
- 최초 주유소 요청의 고정 150ms 대기를 제거했다. 이후 연속 검색 범위 변경에는 기존 150ms 지연을 적용한다.
- 휴게소를 다시 조회할 때 기존 데이터를 즉시 지우지 않아, 조회 중 기존 마커가 불필요하게 사라지지 않는다.

### 조회 결과 캐시

- Next.js의 `use cache`, `cacheLife`, `cacheTag`를 사용한다. 새 의존성은 추가하지 않았다.
- 서버 캐시는 60초 후 재검증 대상이 되며, 120초가 지나면 새 데이터를 기다린다. 기본 메모리 캐시이므로 인스턴스 재시작·콜드 스타트 시 다시 조회할 수 있다.
- 휴게소는 공통 스냅샷을 캐시한다. 주유소는 EX/전체 원본별 공통 스냅샷을 캐시한 후 요청받은 반경·지도 경계를 적용한다. 사용자별 좌표를 서버 캐시 키로 저장하지 않는다.
- 노선 주유소 조회는 노선별 결과를 캐시하며, 기존 노선 근접 거리 조건을 유지한다.
- 관리자 조회와 `x-map-fresh: 1` 요청은 서버 캐시를 우회한다. 명시적인 다시 조회와 오류 후 재시도에도 이 헤더를 사용한다.
- 관리자 저장·EX 동기화·유가 Cron·음식 Cron이 성공하면 관련 태그를 즉시 만료시킨다. DB를 직접 수정하는 외부 CLI 작업은 이 태그를 만료시키지 않으므로 최신 조회 또는 시간 기반 만료로 확인해야 한다.
- 브라우저 주유소 검색 캐시는 각 탐색 화면의 메모리에만 보관한다. TTL 30초, 최대 20개 검색 범위로 제한하고 원본·노선·좌표·반경이 다른 검색은 분리한다. 수동 새로고침과 저장 시 이전 범위의 캐시도 지운다.
- HTTP 응답은 `no-store`를 유지하고, 조회 성능은 위 서버 캐시와 명시적인 브라우저 메모리 캐시로 개선한다.
- API의 `Server-Timing: map-query;dur=...` 헤더에서 서버 조회 구간의 소요 시간을 확인할 수 있다.

### 마커 변경분 갱신

- 지도 레이어가 `update()`를 제공하며, 검색 결과가 변해도 기존 레이어·클러스터러·유지되는 마커 객체를 재사용한다.
- 추가·제외·좌표·아이콘·그룹 구성 등 표시 단위가 달라진 항목만 생성·제거한다. 클러스터 변경분을 일괄 반영한 후 한 번 다시 그린다.
- 음식·유가 등 상세 데이터 변경은 마커 생성 기준에서 분리했다. 클릭 시 최신 레코드를 사용하고 선택된 카드도 최신 데이터로 갱신한다.
- 최초 데이터가 비어 있다가 EX 주유소가 추가되어도 올바른 아이콘을 사용하도록 이미지 생성을 지연하고 재사용한다.
- 휴게소·주유소 연결은 원본 데이터가 바뀔 때만 계산한다. 검색·필터와 상세 연결 목록은 이를 공유한다. 연결 목록 조회는 휴게소별 반복 전체 검색 대신 Map 인덱스를 사용한다.

## 검증 결과

- 관련 단위 테스트 36개 통과: 캐시 만료·범위 격리·용량 제한·초기화, 마커 재사용·추가·제외·최신 데이터, 시설 연결·필터, Cron 인증·오류 처리.
- SDK 모의 브라우저 시나리오 6개 통과: 모바일/PC 양방향 유가·주유소 이동, 줌 재조회, 검색 시 마커 재사용, 동일 반경 복귀 시 요청 재사용 및 재시도, 지도 응답과 독립적인 음식 메뉴 조회.
- 실제 Kakao SDK 시나리오 10개 통과: 모바일/PC의 실패 후 재시도, 목록 선택·줌·화면 크기 변경, 선택 해제, 클러스터 목록·검색·방향 필터, 동일 좌표 그룹.
- 실제 SDK 테스트의 과거 5개 통합 마커 기대값을 현재 정책인 휴게소 4개·주유소 2개의 정확한 이름 목록 비교로 수정했다. 지도 표시 정책은 이번 작업에서 바꾸지 않았다.
- 실제 DB를 읽는 로컬 프로덕션 API 검증 1개 통과: 캐시 응답의 수집 시각 재사용, 최신 조회 우회, 음식 요약 제거, 서로 다른 위치 반경·지도 경계의 결과가 DB 직접 조회와 일치함을 확인했다. 이 테스트는 DB를 수정하지 않는다.
- 변경 파일 ESLint, TypeScript, 프로덕션 빌드 통과.

### 로컬 프로덕션 서버 측정 예시

| API | 최초 요청 | 캐시 조회 | 최신 DB 조회 | 반환 건수 |
| --- | ---: | ---: | ---: | ---: |
| `/api/rest-areas` | 785ms | 10ms | 94ms | 270 |
| `/api/gas-stations?source=ex` | 166ms | 9ms | 87ms | 226 |

실제 Supabase DB를 사용한 단일 측정 예시다. 최초 요청에는 모듈 초기화와 DB 연결 등이 포함될 수 있어, 이를 순수한 렌더링 시간이나 개선 전 기준값으로 해석하지 않는다. 캐시 효과는 같은 실행에서 측정한 캐시 조회와 최신 DB 조회를 비교한다. 실제 배포환경의 지연·콜드 스타트·모바일 기기 성능은 별도로 측정해야 한다.

## 재현 명령

프로덕션 빌드:

```powershell
node node_modules/next/dist/bin/next build
```

SDK 모의 브라우저 검증:

```powershell
node scripts/run-playwright-e2e.mjs e2e/kakao-map-zoom.spec.ts
```

실제 DB 읽기 전용 캐시·범위 검증:

```powershell
$env:E2E_READONLY_DB = '1'
node scripts/run-playwright-e2e.mjs e2e/map-data-cache.spec.ts
```

실제 Kakao SDK는 등록된 주소에서 앱을 실행한 후 검증한다. 기본 주소는 `http://localhost:3000`이다.

```powershell
node scripts/run-marker-visibility-e2e.mjs
```

운영 배포 후에는 API 응답 시간과 `Server-Timing`, 첫 마커 표시 시간, 필터·줌 뒤 안정화 시간을 분리해 확인한다. 배포 리전은 이번 작업에서 변경하지 않았다.
