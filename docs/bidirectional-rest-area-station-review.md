# 양방향 휴게소·주유소 미매칭 검증표

조회일: 2026-10-22 (한국시간)

최초 작성 시 Supabase DB를 읽기 전용으로 조회했으며, 이후 사용자 검증 결과를 코드와 DB에 반영했다. 아래 최신 결과와 최초 조사 당시의 스냅샷을 구분한다.

## 사용자 검증 반영 결과 (2026-10-22)

양방향 휴게소 **14곳 모두 주유소가 1곳 이상 연결됨**을 DB 재조회와 실제 매칭 함수 실행으로 확인했다. 미매칭 휴게소는 **5곳 → 0곳**이다. 모든 방향의 주유소까지 연결되었다는 의미는 아니며, 김해금관가야의 부분 연결 검토는 남아 있다.

좌표는 해당 휴게소의 DB 대표 좌표와 같게 반영했다. 휴게소 테이블에는 주소 컬럼이 없어, 수집된 휴게소 원천 주소와 카카오 좌표→주소 조회를 대조해 보정 주소를 확정했다.

- 원천의 잘못된 주소는 추적성을 위해 `source_location`에 그대로 보존한다. 서비스가 표시하는 정규화 주소·좌표를 보정했다.
- 연결 예외와 위치 보정 기준: `lib/verified-rest-area-stations.ts`.
- 명칭 예외는 검증된 원천 코드와 지정 휴게소에만 적용하며 노선·양방향·300m 거리 검증은 유지한다.
- 처인·고삼호수의 NULL 방향은 `normalizeExGasStations`에서 검증된 원천 코드별로 보완한다. 원천 코드의 `-`와 원본 방향 필드는 변경하지 않는다.
- `synchronizeExStations`는 검증 위치를 캐시·주소 검색보다 우선 적용해, 원천 주소가 바뀌어도 보정값이 유지된다. 기존 수동 주소 검색 매핑보다도 우선한다.
- 현재 위치 보정은 검증일의 고정 좌표다. 휴게소 대표 좌표를 나중에 수정하면 이 보정 기준도 함께 재검증해야 한다.
- DB 반영 스크립트: `node scripts/apply-verified-station-locations.mjs`는 읽기 전용 미리보기, `--apply`를 붙이면 해당 2건만 한 트랜잭션으로 갱신한다. 휴게소 좌표가 검증 기준과 다르면 중단한다.
- 검증: 관련 단위 테스트 26개, TypeScript, 변경 모듈 ESLint 통과. DB 재조회로 두 주유소 주소·좌표와 대상별 연결 수를 확인했다.

아래 표와 개별 체크리스트는 **반영 전 조사 기록**이다. 이전 좌표와 미매칭 사유를 보존하며 최신 상태는 위 반영 결과를 기준으로 한다.

- [ ] EX 주유소 주소·좌표 보정은 다음 동기화에서도 유지되도록 수동 주소 매핑 등 기존 보정 경로를 검토한다. 관련 코드: `data/ex-station-geocode-overrides.json`, `lib/ex-station-geocode-overrides.ts`.
- [ ] 주유소 이름이나 방향으로 `source_key`를 임의 재생성하지 않는다. 원천 식별자 변경은 별도 검토한다.
- [ ] 매칭 규칙을 바꾸는 경우 단방향 휴게소의 반대 방향 주유소가 잘못 연결되지 않는지 관련 테스트로 확인한다.
- [ ] 모바일 바텀시트·PC 모달의 연결 주유소 목록, 유가 범위, 개별 주유소 지도 이동을 확인한다.
- [ ] 검증·반영 후 미매칭 수를 다시 집계한다.

관련 구현: `lib/facility-places.ts`의 `mergeFacilityPlaces`, `isBidirectionalDirection`.
