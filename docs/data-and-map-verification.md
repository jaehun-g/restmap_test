# 데이터 정합성 및 지도 표시 점검

이 문서는 이전 작업에서 발견한 문제와 직접 확인할 항목을 모은 점검표다. 과거 검증 결과와 현재 DB 상태는 다를 수 있으므로 과거 건수를 현재 확정 수치로 해석하지 않는다.

현재 반영된 로컬 코드 커밋: `3f81ab9`(DB 갱신 트리거), `6bfba37`(연결·방향·검색 보정), `3381f55`(지도 가격 카드 갱신). 커밋은 운영 배포를 의미하지 않는다.

## 우선 확인할 항목

- [ ] **밀양영남루 휴게소·주유소:** 지도에서 함양 방향과 밀양 방향의 휴게소·주유소 위치와 연결 관계를 확인한다. 카카오와 원천 자료의 밀양·울산 방향 표기가 엇갈리므로 실제 차량 진입 방향은 별도로 확인한다. 표준 코드 `000602` 휴게소와 주유소 ID `58`은 밀양 방향으로 표시하도록 보정했다.
- [ ] **반대 방향 주유소 연결:** 선산·문경·서여주·부여백제에서 휴게소 상세에 연결된 주유소의 이름, 방향, 위치와 유가가 해당 휴게소에 맞는지 확인한다. 과거 검증에서 주유소 이름과 원천 방향 필드가 충돌했다.
- [ ] **남은 주유소 미연결:** 성남(구리), 구리남양주(판교), 김해금관가야(기장) 주유소의 위치·방향·대응 휴게소를 확인한다. 김해금관가야는 기존 양방향 휴게소 좌표와 약 1.25km 떨어져 있다.
- [ ] **수정 코드 배포 및 화면 확인:** 영덕·포항·김제 양방향, 선산·문경·서여주·부여백제의 방향과 연결 보정 코드를 배포하고 휴게소 인포윈도우에서 주유소 가격이 표시되는지 확인한다. 배포 전 기존 코드로 전체 동기화하면 DB 방향·노선 보정값이 원천값으로 되돌아갈 수 있다.
- [ ] **다음 Cron 실행 확인:** DB 컬럼 변경 후 주유소 갱신 트리거 오류를 수정했다. 다음 가격·음식 Cron의 실행 로그와 DB 갱신 시각을 확인한다. 기존 DB 기록만으로 Vercel Cron이 직접 실행했는지는 확정할 수 없다.
- [ ] **언양(서울) 가격 미제공:** 주유소는 언양(서울 방향)휴게소에 연결되지만, 확인한 원천 가격은 휘발유·경유·LPG 모두 0으로 가격 미제공 상태다. 이후 유효한 가격이 제공되는지 확인한다.
- [ ] **서하남 가격 표시:** 서하남행복드림쉼터와 서하남(판교)주유소는 로컬 코드에서 연결된다. 주유소가 늦게 조회되면 열린 인포윈도우가 갱신되지 않던 문제를 수정했으며, 배포 후 실제 화면에서도 가격 표시를 확인한다.
- [ ] **진행 방향 입력 규칙:** `lg_route_direction`은 상행·하행·양방향 또는 미확인(NULL)으로 관리하고 지명은 `lg_direction_label`에 둔다. DB를 정리하고 재수집·관리자 입력을 수정했으므로 배포 후에도 유지되는지 확인한다.
- [ ] **좌표 누락:** 점곡(상주 방향), 군자행복드림쉼터, 구리남양주행복드림쉼터의 실제 위치와 방향을 확인한다. 이전 DB 조회에서는 세 곳의 좌표가 없어 지도에 표시할 수 없었다.
- [ ] **주유소 보정 좌표:** 과거에 주유소 21곳의 좌표를 대응 휴게소 좌표에 맞췄다. 이는 주유기나 주유소 건물의 실제 좌표를 확인했다는 의미가 아니므로 정확한 핀 위치가 필요하면 현장·지도 자료와 대조한다.
- [ ] **배포 환경 지도:** 실제 휴대폰에서 첫 접속과 재접속 속도, 확대·축소, 반경 변경, 전체화면 및 상세 화면을 확인한다.

## 데이터 정합성 이력

### 휴게소 위치·방향

밀양영남루 함양 방향과 밀양 방향의 기존 좌표는 서로 반대편에 저장되어 있었다. 카카오 장소 검색 결과와 주소를 기준으로 각각 보정했고, 해당 주유소의 좌표와 표시 이름도 조정했다. 실제 주행 방향은 위 점검 항목으로 남는다.

부안 쉼터 상·하는 서울·목포 방향으로, 양북임시 상·하는 울산·포항 방향으로 표기했다. 표준 코드에 따른 보정과 원천 이름 매핑을 추가해 재수집 시에도 유지하도록 했다. 현장 표지판과 일치하는지는 필요 시 확인한다.

민자 구간으로 확인된 휴게소 23곳은 서비스 대상에서 제외했고 재수집 시 다시 추가되지 않도록 목록을 적용했다. 기존 API에 민자 여부 구분이 없어 새로 수집된 시설은 별도 검토가 필요하다.

### 휴게소·주유소 연결

EX 주유소는 휴게소와 이름, 노선, 방향, 300m 이내 거리 등을 대조해 연결한다. 원천 방향 필드로 연결할 후보가 없을 때는 주유소 이름에 적힌 방향을 보조 조건으로 사용한다. 명칭 예외와 양방향 시설은 별도로 보완했다.

2026-10-22 검증 당시에는 EX 주유소 226곳 중 217곳이 휴게소에 연결됐고, 9곳은 연결되지 않았다. 같은 시점에 주유소가 있다고 등록된 단방향 휴게소 9곳에도 연결이 없었다. 두 숫자는 집계 대상이 다르며 이후 데이터가 변경되었으므로 현재 수치가 아니다.

과거 미연결 원인에는 노선 불일치·누락, 서로 다른 시설 이름, 좌표 거리 초과, 방향 또는 휴게소 좌표 누락이 있었다. 연결 후보는 실제 같은 시설이라는 확정이 아니며 반대 방향과 공유 시설 여부를 확인해야 한다.

### 2026-11-09 최근 점검 상태

영덕(영덕), 포항(포항), 김제(전주·새만금)는 방향·노선 보정 후 로컬 코드에서 해당 휴게소에 연결되는 것을 확인했다. 의왕청계(일산)는 휴게소 이름, 주유소 방향과 좌표를 보정했고, 서하남은 주유소 이름과 쉼터 방향을 보정해 각각 연결했다. 주유소 보정값은 DB에도 반영했으며, 재동기화 보정 코드는 배포 전이다.

이후 현재 DB와 로컬 매칭 규칙으로 재조회한 결과 EX 주유소 226곳 중 **223곳이 연결되고 3곳이 미연결**이다. 휴게소 기준으로는 **31곳이 미매핑**이며, 주유소 있음으로 등록된 곳은 0곳, 없음 1곳, 유무 미확인 30곳이다. 휴게소 기준과 주유소 기준은 서로 다른 집계다. GS는 포함하지 않았다.

| --- | --- |
| 성남(구리) | 대응 휴게소 레코드와 주유소 위치 |

## 노선 선형 점검

고속도로 하이라이트는 `tb_highway_routes`의 노선별 선형을 사용한다. 과거 선형의 누락·단순화와 노선명 중복 문제를 확인해 통영대전선·동해선 등의 선형과 별칭을 정리했다. 이전 QA 기록은 일부 선형 교체 전 자료다.

이전 현재 DB 조회에서는 좌표가 있는 휴게소 244곳을 각 노선 선분과 비교했을 때 500m 이상 떨어진 곳은 없었고, 가장 먼 곳은 내린천 양방향 약 325m였다. 이 거리는 본선까지의 최단 직선거리이며 좌표의 정확성이나 실제 진입 가능 여부를 보장하지 않는다. 이후 밀양영남루 좌표가 수정되었으므로 필요 시 전체 거리를 다시 계산한다.

- [ ] 카카오 지도에서 경부선·서울양양선·서해안선·인천대교선·함양울산선·영동선의 하이라이트를 확대하고 실제 도로와 겹치는지 확인한다.
- [ ] 새 출발지→도착지 경로 기능을 만들 때는 고속도로 전체 노선 선형과 실제 주행 경로를 구분하고, 반대 방향 휴게소와 진입로를 별도로 검증한다.

## 지도 표시 및 성능 이력

기존에 발견한 클러스터 깜빡임, 확대 후 마커 누락, 반경 축소 후 잔류 마커, 전체화면 흰 여백과 줌 변경, 관리자 상세 모달 표시 문제를 수정했다. 초기 데이터 조회·SDK 로딩·시설 연결 계산도 개선했다. 관련 단위 및 브라우저 테스트와 로컬 성능 측정 기록이 있다.

배포 화면에서 다음을 확인한다.

1. 확대·축소를 반복하고 클러스터가 자연스럽게 분리되며 마커가 빠지거나 깜빡이지 않는지 확인한다.
2. 위치 검색 반경을 줄였다 늘리면서 범위 밖 마커가 남지 않고 범위 안 마커가 다시 나타나는지 확인한다.
3. 전체화면을 켜고 끄며 흰 여백이나 예기치 않은 줌 변경이 없는지 확인한다. 관리자 화면에서는 상세 모달도 연다.
4. 실제 모바일 기기와 네트워크에서 첫 접속·재접속 시 지도와 마커가 표시되는 시간을 확인한다. 로컬 측정 결과를 배포 환경 성능으로 단정하지 않는다.
