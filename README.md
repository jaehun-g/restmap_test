# Cafe24 휴게소 지도 테스트

로컬 Next.js 서버가 Cafe24 MariaDB의 휴게소 정보를 조회하고 카카오맵에 표시합니다.
PC 관리자 화면과 모바일 사용자 화면은 별도 페이지이며 같은 조회 API를 사용합니다.

## 화면

- `/mobile`: 지도 위에 검색창·필터 칩과 하단 목록·상세 패널이 표시됩니다. 마커는 요약 카드를 먼저 열고, 상세보기에서 카드를 유지하며 상세 패널을 엽니다. 목록에서는 상세를 바로 엽니다.
- `/admin`: 휴게소 표·지도·상세정보, 보완 항목 요약, 필터·정렬 및 인증 후 편집을 제공합니다.
- `/`: `/mobile`로 이동합니다. 기기 자동 판별은 하지 않습니다.
- `/api/rest-areas`: DB 조회 결과를 JSON으로 반환하는 GET API입니다.
- `/api/highway-routes?routeName=경부선`: 선택한 노선의 경계와 `[위도, 경도][][]` 좌표를 반환하는 GET API입니다. `test_highway_routes`에 SELECT만 수행합니다.
- `/api/gas-stations`: `test_gscargo`의 GS 주유·충전소와 `test_ex_station_geocodes`의 EX 주유소를 함께 조회합니다. 위치 반경·지도 영역 또는 `routeName` 주변 2km 검색 범위를 지원합니다. 두 출처는 별도 장소로 유지하며, EX의 양수 유가만 인포윈도우·상세정보에 원/L 단위로 표시합니다. EX 정보는 읽기 전용이고, 미확인 시설은 시설 조건 필터에서 제외됩니다.

모바일·관리자에서 통합·휴게소·주유소 보기를 선택할 수 있습니다. 휴게소 조건과 주유소 시설 조건은 각각 적용합니다.
노선 선택 시 주유소는 분리된 노선 구간 각각과의 직선거리 **2km 이내**만 조회하며, 고속도로 소속이나 실제 진입 가능 여부를 뜻하지 않습니다.
관리자는 기존 인증 후 주유소의 이름·연락처·주소·좌표·영업시간·주요 시설을 편집할 수 있습니다.
주유소 ID·GS 코드·내부 운영 코드·결제 항목은 읽기 전용이며, 테이블 구조 변경이나 자동 데이터 적재는 수행하지 않습니다.

검색은 휴게소명과 노선명만 대상으로 합니다. 대소문자를 구분하지 않는 부분 일치이며,
공백으로 나눈 검색어가 모두 일치해야 합니다. 입력은 500ms 후, Enter와 지우기는 즉시 반영됩니다.

- 모바일 노선은 검색 가능한 단일선택 바텀시트입니다. 선택 즉시 반영하고 닫습니다.
- 모바일·관리자에서 노선을 선택하면 파란색 선과 흰색 외곽선으로 해당 노선을 표시합니다.
  분리된 구간은 이어 붙이지 않으며, 휴게소 결과가 없어도 경로는 유지합니다. 전체 노선·조건 초기화에서는 선을 제거합니다.
  노선 선택 시 해당 노선 전체와 휴게소가 보이도록 지도를 맞춥니다. 조회 중·실패 시에는 휴게소 위치로 먼저 맞춥니다.
  모바일 노선 필터는 현재 위치 반경·지도 영역 조건보다 우선하며, 검색어·시설·라운지 조건과 거리순 정렬은 유지합니다.
  노선 선택 중에는 반경 원·지도 내 재검색을 숨기며, 전체 노선·조건 초기화에서는 저장된 위치 검색 범위를 다시 적용합니다.
  성공한 경로는 브라우저 메모리에 5분간 보관합니다.
  좌표 오류·조회 실패는 지도 위 안내와 다시 시도로 처리하며 휴게소 지도는 유지합니다.
- 편의시설은 라운지를 제외한 11개 항목을 다중선택합니다. 선택한 시설이 모두 있는 휴게소만 표시합니다.
  모바일에서 체크 즉시 결과가 바뀌며, 지도 중심·확대 수준과 위치 검색 범위는 유지합니다.
- 모바일 라운지 토글 OFF는 전체, ON은 라운지 있음만 표시합니다.
  노선명 없는 휴게소도 유지하되 미등록 안내·옵션과 라운지 미확인 상태는 숨깁니다.
  노선 선택을 제외한 검색·필터·조건 초기화·다시 조회는 지도 중심·확대 수준과 위치 검색 범위를 유지하고 결과만 갱신합니다.
- 관리자는 노선 미등록과 라운지 있음·없음·미확인을 구분해 조회합니다.
  23개 필드의 오름·내림차순 정렬을 지원하고 미등록 값은 항상 마지막에 표시합니다.
  정렬은 표 헤더에서 조작합니다. 기본 표에 없는 필드는 ‘전체 컬럼 보기’로 표시한 뒤 제목을 누릅니다.
  표의 첫 컬럼 `No`는 현재 검색·정렬 결과의 게시판식 역순 번호(결과 건수부터 1까지)입니다. DB ID는 ‘전체 컬럼 보기’에서 별도로 확인·정렬합니다.
  편의시설 요약을 펼치면 12개 시설 상태를 확인할 수 있습니다.
- 검색과 필터는 AND로 결합합니다. 다시 조회에서는 조건을 유지하고 브라우저 새로고침에서는 초기화합니다.
- 파란 휴식 아이콘은 일반 휴게소, 주황 트럭 아이콘은 화물차 라운지가 있는 휴게소입니다.

행 추가·삭제, 스키마 변경, 자동 새로고침은 제공하지 않습니다.

## 현재 위치와 지도 내 재검색

- 첫 진입과 **내 위치** 버튼에서만 브라우저 위치를 요청합니다. 연속 추적은 하지 않습니다.
  정확도 우선, 10초 제한, 캐시 사용 없음으로 조회합니다.
  관리자 화면은 버튼을 눌렀을 때만 위치를 요청합니다. 편집 중에는 위치 버튼과 지도 내 재검색을 잠급니다.
  지도 우측 하단의 확대·축소 버튼 대신 **내 위치** 버튼을 표시합니다. 확대·축소는 지도 제스처 또는 마우스 휠로 조작합니다.
- 위치 확인 성공 시 내 위치를 중심으로 반경 **15km**를 검색하고 파란 위치 점과 반투명 원을 표시합니다.
  최초 지도 배치의 줌 레벨을 기준으로, 한 단계 축소하면 30km, 한 단계 확대하면 7.5km가 됩니다.
  반경의 중심은 실제 내 위치에 고정하며 드래그한 지도 중심을 따라가지 않습니다.
  반경 숫자는 원의 오른쪽 가장자리에 붙은 배지로 표시하며, 줌에 따른 반경 변화와 함께 값·위치를 갱신합니다.
  노선 선택 시 원과 배지를 함께 숨기고, 노선을 해제하면 함께 복원합니다.
- 줌 변경이 끝나면 반경·목록·마커·건수가 함께 갱신됩니다. 결과 갱신 때문에 지도를 다시 이동하지 않습니다.
  목록은 실제 내 위치에서 가까운 순이며 직선거리를 표시합니다.
- 드래그·줌 뒤 **지도 내 재검색**을 누르면 클릭 시점의 지도 전체 화면 영역으로 검색합니다.
  모바일에서는 헤더·하단 패널이 덮고 있는 영역을 제외한 실제 보이는 지도 영역을 사용하며, 반경 조건과 교차하지 않고 영역 조건으로 교체합니다.
  이후 드래그·줌에서는 확정한 결과를 유지하고 버튼을 다시 눌러 갱신합니다.
  내 위치 반경 원과 반경 표시는 재검색 후에도 유지하며 현재 줌 레벨에 맞춰 크기만 갱신합니다.
  원의 중심은 내 위치에 고정하고, 별도 ‘지도 영역 검색’ 표시로 현재 결과의 검색 범위를 안내합니다.
- **내 위치**는 좌표를 다시 확인해 반경 15km로 복귀하고 기준 줌 레벨을 다시 설정합니다.
  노선을 선택한 상태에서는 노선 선택을 해제한 뒤 위치를 조회합니다. 늦게 도착한 위치 응답은 선택 노선의 지도 화면을 이동시키지 않습니다.
  위치 응답을 기다리는 동안 실행한 지도 내 재검색은 늦게 도착한 위치 응답으로 덮어쓰지 않습니다.
- 최초 위치 확인 실패 시 전체 조회 화면을 유지하고 지도 내 재검색을 사용할 수 있습니다.
  이후 실패는 기존 검색 범위를 유지합니다. 권한 거부·시간 초과·위치 확인 불가를 구분해 안내합니다.
- 위치 표시와 휴게소 거리 계산은 브라우저 메모리의 좌표를 사용합니다.
  GS 주유소 범위 조회에는 중심·반경 또는 지도 경계 좌표를 앱 서버로 전달해 SELECT하며, 위치 이력을 DB에 저장하지 않습니다.

브라우저 위치 조회에는 사용자 권한과 보안 연결이 필요합니다. PC의 `http://localhost:3000`은 개발용 예외지만,
휴대폰에서 접속하는 `http://PC의내부IP:3000`은 보안 연결이 아니므로 위치 조회가 제한됩니다.
이 경우 화면의 안내에 따라 지도 내 재검색을 사용할 수 있습니다. 실제 휴대폰 위치 조회 검증에는 HTTPS가 필요하며,
이번 변경에는 인증서·HTTPS 서버 설정을 포함하지 않습니다.
[브라우저 위치 API 조건](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)

## 환경변수

프로젝트 루트의 `.env.local`에 [.env.example](.env.example)의 항목을 설정하세요.
이미 `.env`에 설정되어 있다면 Next.js가 자동으로 읽습니다. `.env.local`이 더 높은 우선순위입니다.
비밀값이 있는 환경변수 파일은 Git에서 제외됩니다. 기존 설정 파일을 덮어쓰지 마세요.

| 환경변수                        | 내용                                                                                         |
| ------------------------------- | -------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_KAKAO_MAP_APP_KEY` | 카카오 JavaScript 키. REST API 키 또는 Admin 키가 아닙니다.                                  |
| `KAKAO_REST_API_KEY`             | EX 주유소의 신규·변경 주소를 좌표로 변환하는 서버 전용 카카오 REST API 키                    |
| `EX_OPEN_API_KEY`                | 한국도로공사 `curStateStation` 호출에 쓰는 서버 전용 Open API 키                             |
| `DB_HOST`                       | Cafe24 DB 외부 접속 호스트                                                                   |
| `DB_PORT`                       | DB 포트. 기본값 3306                                                                         |
| `DB_USER`                       | DB 사용자                                                                                    |
| `DB_PASSWORD`                   | DB 비밀번호                                                                                  |
| `DB_NAME`                       | `test_lounge`가 있는 데이터베이스 이름                                                       |
| `DB_SSL`                        | 신뢰 가능한 인증서로 TLS 접속을 지원할 때 `true`. 기본값 `false`                             |
| `ADMIN_PASSWORD`                | 이 페이지의 관리자 편집 잠금 해제 암호. DB 접속 암호와 별개이며 미설정 시 조회만 가능합니다. |

카카오디벨로퍼스에서 카카오맵을 활성화하고 해당 JavaScript 키의 SDK 도메인에
`http://localhost:3000`을 등록하세요. `127.0.0.1`이나 다른 포트로 접속하면 해당 주소도 별도로 등록해야 합니다.
DB 외부 접속을 위해 Cafe24 MySQL 외부 IP 허용 목록에 현재 PC의 공인 IP를 등록해야 합니다.
환경변수를 변경하면 개발 서버를 재시작하세요.

EX 주유소 동기화 전에 한 번만 다음 테이블을 준비하세요.

```powershell
npm.cmd run db:setup-ex-station-geocodes
npm.cmd run db:setup-ex-station-geocode-overrides
```

- [카카오 Web SDK 가이드](https://apis.map.kakao.com/web/guide/)
- [카카오맵 활성화 안내](https://developers.kakao.com/docs/ko/kakaomap/common)
- [Cafe24 MySQL 외부 접속 안내](https://help.cafe24.com/faq/web-hosting/introduce/setup-management/webhosting_mysql_external_ip_access/)

## 실행

PowerShell에서 실행 정책에 막히지 않도록 `npm.cmd`를 사용합니다.

```powershell
npm.cmd run dev -- --hostname localhost --port 3000
```

- 모바일: http://localhost:3000/mobile
- PC 관리자: http://localhost:3000/admin

같은 네트워크의 휴대폰 등에서 접속하려면 기존 개발 서버를 종료한 뒤 다음 명령으로 실행하세요.

```powershell
npm.cmd run dev -- --hostname 0.0.0.0 --port 3000
```

`http://PC의내부IP:3000/mobile`로 접속합니다. Windows 방화벽의 TCP 3000 접근이 허용되어 있어야 하고,
카카오 JavaScript SDK 도메인에도 `http://PC의내부IP:3000`을 등록해야 합니다.
`0.0.0.0`은 서버의 수신 설정이며 실제 접속 주소에는 PC의 IP를 사용합니다.

현재 Next.js 개발 서버는 핫리로드 WebSocket의 접속 출처도 확인합니다. IP 주소로 개발하며
변경사항을 자동 반영하려면 `next.config.ts`의 기존 설정에 `allowedDevOrigins: ["192.168.0.10"]`처럼
실제 PC IP를 추가하고 서버를 재시작하세요. 여기에는 스킴·포트 없이 호스트만 입력합니다.
이는 [Next.js 개발 출처 설정](https://nextjs.org/docs/app/api-reference/config/next-config-js/allowedDevOrigins)이며
카카오 SDK 도메인 등록과는 별개입니다.

모바일 화면은 PC 브라우저에서도 최대 480px의 앱 화면으로 표시됩니다.
관리자 화면은 PC용 레이아웃으로 별도 구현했습니다.

## 관리자 편집과 DB 변경 범위

DB 코드는 `lib/db.ts`에만 있으며 `server-only` 모듈입니다.
브라우저에는 DB 접속 정보가 포함되지 않습니다.
조회는 `test_lounge`의 고정된 23개 컬럼만 읽습니다.
관리자가 인증 후 **변경사항 저장** 버튼을 실행한 경우에만 기존 행의 ID를 제외한 22개 컬럼을 수정할 수 있습니다.
요청에서 SQL·테이블명·임의 컬럼을 입력받지 않습니다. EX 주유소 동기화만 별도 인증 API와 고정된 테이블·컬럼으로 최신 스냅샷을 upsert하고, 원본 목록에서 사라진 EX 행을 삭제합니다.
첫 화면 진입과 명시적인 다시 조회/재시도에서만 조회합니다.
연결 풀은 최대 3개 연결과 제한된 대기열을 사용합니다.

`/admin`의 관리자 인증에서 환경변수의 암호를 입력해 잠금을 해제한 뒤 휴게소를 선택하고 **정보 수정**을 누릅니다.
기본정보·노선·좌표·시설·주차를 편집하고 변경사항 저장 또는 취소를 선택합니다.
미저장 상태의 행 이동·닫기·다시 조회·편집 잠금에는 변경사항 폐기 확인을 표시합니다.
숫자 입력란의 Enter만으로는 저장하지 않습니다.

관리자 인증 후 헤더의 **EX 동기화**를 누르면 한국도로공사 API의 전체 응답을 검증한 뒤 EX 주유소 최신값을 저장합니다. 신규 또는 주소·오버라이드가 바뀐 주유소만 지오코딩하며, 완료 후 EX 목록을 다시 조회합니다. 개발 중 터미널에서 직접 실행하려면 다음 명령을 사용하세요.

```powershell
npm.cmd run sync:ex-stations
```

- `GET /api/admin/session`: 설정 여부·인증 상태·만료 시각을 반환합니다.
- `POST /api/admin/session`: `{ "password": "…" }`로 인증합니다. 서버 메모리 세션은 8시간 뒤 만료하며 서버 재시작 시 초기화됩니다.
  쿠키는 HttpOnly·SameSite=Strict이고 HTTPS에서는 Secure를 적용합니다. 인증 실패는 5분간 5회로 제한합니다.
- `DELETE /api/admin/session`: 세션을 폐기하고 편집을 잠급니다.
- `POST /api/admin/ex-stations/sync`: 동일 출처의 관리자 인증 세션에서만 EX 주유소 동기화를 시작합니다. 실행 중 중복 요청은 `409`를 반환합니다.
- `PATCH /api/admin/rest-areas/[id]`: `{ changes, expectedRevision }`을 받습니다.
  변경 필드는 API의 camelCase 이름이며 시설은 `facilities` 내부의 DB 필드명과 `true`·`false`·`null`을 사용합니다.
  이름은 필수이고 테이블의 문자열 길이·기존 UTF-8 문자 집합·좌표 범위/7자리·주차 정수 조건을 서버에서도 검사합니다.
  좌표 변경 시 위도·경도는 함께 등록하거나 함께 미등록이어야 합니다.

모든 변경 요청은 동일 출처와 인증 세션을 검증합니다. 조회 결과의 `revision`을 저장 요청에 포함하고,
트랜잭션에서 해당 행을 잠금 조회해 비교합니다. 충돌은 HTTP 409로 중단하며 입력 초안을 유지합니다.
변경된 허용 컬럼만 매개변수화한 UPDATE로 저장하고 성공 응답을 목록·필터·정렬·마커에 반영합니다.
연결 정보·관리자 암호·원시 SQL 오류는 API 응답이나 클라이언트 번들에 포함하지 않습니다.

조회 결과는 `lib/rest-areas.ts`에서 정규화합니다.

- DECIMAL 문자열을 숫자로 변환하고 위도·경도 범위를 검사합니다.
- 이 Cafe24 DB가 바이너리 메타데이터로 반환하는 UTF-8 텍스트는 앱에서 문자열로 변환합니다.
- 좌표가 없거나 올바르지 않은 행은 지도에서 제외하고 목록에서는 조회할 수 있습니다.
- 시설 값 `1`, `0`, `NULL`을 각각 있음, 없음, 미확인으로 구분합니다.
- 주차 대수 `0`을 유지하며 `NULL`은 정보 없음으로 표시합니다.
- 이름 등 DB 문자열은 React 텍스트 또는 `textContent`로 출력합니다.
- 연결 오류 시 샘플 데이터로 대체하지 않고 실제 오류 상태를 표시합니다.

## 검증

스타일과 공통 UI 작성 방법은 [디자인 시스템](docs/design-system.md)을 참고하세요. Tailwind CSS 4의 색상·폰트 토큰, 공통 컨트롤, 화면 배치와 SDK 카드의 스타일 경계를 정리했습니다.

Node.js 24에서 추가 테스트 도구 없이 실행합니다.
테스트는 고정된 메모리 데이터, DB 대역, 카카오 SDK·DOM 대역을 사용하며 실제 DB에 접속하거나 쓰지 않습니다.
테스트가 검색·필터·정렬·입력 검증·인증/만료·동일 출처·revision 충돌·롤백·마커 종류/복원·카드 유지·지도 위치 유지 정책과 위치 검색·줌 반경·지도 내 재검색·위치 요청 충돌을 확인합니다.
노선 좌표 검증·캐시·요청 순서·선 제거·브라우저 fetch 호출 문맥과 노선 우선 검색·전체 노선 화면 배치도 확인합니다.
위치 테스트도 브라우저 API 대역을 사용하며 실제 사용자 좌표를 요청하지 않습니다.

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

브라우저 수동 확인 시 다음을 점검하세요.

- 모바일·관리자에서 경부선·영동선·수도권제1순환선을 선택하고, 빠른 변경·전체 노선·조건 초기화에서 이전 선이 남지 않는지 확인합니다.
  휴게소 결과가 0개여도 선택 노선이 표시되어야 하며, 경로 오류에서 마커·위치 검색은 유지되고 다시 시도로 복구할 수 있어야 합니다.
- 모바일에서 15km 반경 또는 지도 영역 검색 후 멀리 있는 노선을 선택하면 해당 노선 휴게소가 표시되고 지도에 노선 전체가 보여야 합니다.
  노선 화면의 줌·드래그와 늦은 위치 응답은 휴게소 결과를 반경으로 제한하지 않아야 합니다.
  전체 노선·조건 초기화에서는 저장된 위치 검색 범위가 복구되고, 내 위치에서는 노선 선택이 해제되어야 합니다.

1. `/` 접속 시 `/mobile`로 이동하고 조회된 휴게소 마커가 나타나는지 확인합니다.
2. 검색어를 여러 개 입력하고 휴게소명·노선명만 일치하는지, Enter·지우기가 즉시 반영되는지 확인합니다.
3. 노선 시트에서 검색·선택·자동 닫기를, 편의시설 시트에서 다중선택·시설 AND·조건 유지와 시트 종료 후에도 지도 중심·확대 수준 유지를 확인합니다.
4. 라운지 토글과 조건 초기화에서 중심·확대 수준이 그대로인지, OFF에서 전체·ON에서 있음만 표시하는지 확인합니다. 노선 미등록 안내와 라운지 미확인 상태는 모바일에 나타나지 않아야 합니다.
5. 마커 선택 → 요약 카드 → 상세보기에서도 카드가 유지되는지, 카드 내부에 스크롤이 없는지 확인합니다. 목록 선택 → 상세를 확인하고 필터에서 제외된 휴게소의 카드·상세·선택이 해제되는지 점검합니다.
6. 관리자 보완 항목 요약·적용 조건 배지·시설 펼치기와 표 헤더 정렬을 확인합니다. ‘전체 컬럼 보기’에서 23개 필드를 정렬할 수 있어야 하며, 정렬만으로 지도 위치·선택이 바뀌면 안 됩니다.
7. 관리자 인증 후 편집에서 기존값·변경 표시·취소·행 이동 시 폐기 확인을 점검합니다.
   실제 운영 DB에서는 화면 점검을 위한 임의 저장을 하지 말고 필요한 데이터 보완 때만 저장하세요.
8. PC 전체 보기·확대/축소·패널 전환·카드 경계 보정과 빈 결과의 초기화, 키 또는 DB 오류의 재시도를 확인합니다.
9. 모바일 최초 위치 허용 시 15km, 한 단계 축소 30km·확대 7.5km, 거리순 목록·파란 위치 점을 확인합니다.
   드래그 후에도 원 중심은 내 위치에 유지되고 드래그 시작 시 선택 카드가 닫혀야 합니다.
10. 지도 내 재검색은 현재 화면 영역으로 조건을 교체하고, 추가 줌·드래그에서는 버튼을 다시 누르기 전까지 결과를 유지해야 합니다.
    재검색 후에도 내 위치 반경 원·반경 표시는 유지되고 현재 줌 레벨을 따라 크기만 갱신되어야 합니다.
    내 위치 버튼으로 복귀하면 15km가 됩니다. 위치 권한 거부와 HTTP IP 접속에서도 전체 조회·지도 내 재검색이 가능해야 합니다.

이번 실행에서는 실제 SELECT 조회로 휴게소 215개와 유효 좌표 215개, 전체 행의 revision을 확인했습니다.
인증 없는 저장과 다른 출처의 요청이 거절되는 것도 확인했습니다. 실제 운영 DB에 저장 테스트는 실행하지 않았습니다.
브라우저 제어 기능이 제공되지 않아 실제 화면과 지도 클릭에 대한 시각 검증은 수행하지 못했습니다.
